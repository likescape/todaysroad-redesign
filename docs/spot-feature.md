# 스팟 첫 구현

## 현재 상태: 앱에서 제거

사용하지 않는 POI 이야기 기능을 일반 앱에서 제거했다. 코스 카드의 이야기 영역, 지도 이야기 마커, 산책 중 이야기 버튼, 상세·목록 연결과 코스별 선별 호출을 삭제했다. `/?preview=spots` 진입도 제거했다. 참고 데이터와 `/dev/spots` 카탈로그는 보관하며, 일반 코스·산책·커뮤니티 흐름에서 사용하지 않는다.

아래는 최초 구현 당시의 동작과 검증 이력이다. `scripts/verify-spots.cjs` 역시 이전 UI의 검증 기록이며 현재 앱 흐름에 적용하지 않는다.

## 최초 구현 기록

검토일: 2026-09-09. `docs/spot-implementation-prompt.md`에 따라 단일 에이전트로 구현했다. 현재 프로젝트만 수정했고, `../todays-road-mono/data-discovery/`와 운영 앱은 변경하지 않았다. 작업 시작 전 존재하던 기록·커뮤니티·테마·에셋 변경을 보존했다.

## 구현 범위

- 코스 생성 또는 기존 코스 선택으로 **경로가 정해진 시점**에 주변 이야기를 선별한다. `Course.spots?`는 해당 경로의 연결 스냅샷이며 산책 시작은 같은 Course 객체를 사용한다.
- 코스 카드의 ‘이 길에서 발견할 이야기’, 지도 마커, 산책 중 ‘이 길의 이야기’가 같은 상세를 연다. 목록과 마커의 선택 상태가 일치한다. 상세 닫기·Esc·배경 클릭 및 포커스 복귀를 지원한다.
- 상세를 열어도 타이머·진행 경로·시뮬레이션 위치는 계속 유지된다. 탭·설정·테마 전환에도 진행 중 코스와 스팟은 유지한다. 새 선택·생성·홈 복귀·종료에서는 상세 선택 상태를 초기화한다.
- 스팟은 필수 경유지가 아니다. 0개 코스도 시작·종료할 수 있다. 위치 미검증 후보를 실제 지도에 표시하거나 스팟을 채우기 위해 경로를 다시 생성하지 않는다.
- 라이트·다크 공통 색상 변수를 사용한다. 가까운 두 장소의 지도 버튼은 벌려 놓고 연결선 끝의 점으로 원래 좌표를 표시한다. 작은 화면에서는 카드 본문을 스크롤하며 산책 시작 버튼은 카드 하단에 유지한다. ‘모두 보기’에서 전체 목록을 열 수 있고, 작은 모바일에서는 설명·장식 사진을 접어 조작 공간을 확보한다.
- 서버·인증·수집 파이프라인·경로 엔진·방문 인증·배지·알림·공유 확장은 없다. 기록과 커뮤니티의 모델·저장 키·방문 이력은 확장하지 않았다.

기존 후보의 `eligible_for_automatic_display:false`, `route_match_verified:false`는 변경하지 않았다. 이번 확인은 `docs/data/spot-location-review.json`과 현재 프로젝트의 정제 데이터에 **새 근거**로 남겼다. 일반 검색에서 확인한 제3자 주소 사이트 좌표는 채택하지 않았다.

경의선숲길 키워드 검색은 식당·카페, 대흥동·동교동·연남동 등의 공원 대표점을 반환했다. 신수동 구간의 위치 근거로 충분하지 않으므로 모두 대체 좌표로 사용하지 않았다. 광흥창 터는 영역이 없으므로 사당이나 광흥당의 핀으로 대체하지 않았다. 상권 자료는 영역 기준 호환성이 해결되기 전까지 점 매칭 대상이 아니다. 행사 샘플에는 API 좌표가 있지만 첫 정제 콘텐츠에서 제외했다.

**확인 완료:** 세 점형 후보의 주소/장소 식별과 지오코딩 대표 좌표, 생성된 목업 선분과의 수치적 근접 계산. **미확인:** 현장에서의 위치 정확도, 실제 도로망·보행 접근성·출입구·운영시간·진입 가능성. SDK가 좌표 오차 범위를 제공하지 않아 숫자로 된 정확도를 임의 지정하지 않았다.

## 선별 규칙

1. 이야기 `review=approved`와 근거가 있고, 장소가 `geometry=point`, `location.status=verified`, 좌표와 위치 근거를 모두 가진 후보만 사용한다.
2. `lib/spots.ts`의 `SPOT_CONFIG`: 반경 100m, 최대 3개, 같은 이야기 중복 반경 80m, 행사 사전 노출 30일. 제품 검토용 가정이다.
3. 동네 규모의 equirectangular 근사 투영(미터 단위)으로 **경로 모든 선분의 최근접점**을 계산한다. 선분 내부 투영을 사용하고 끝 밖은 끝점으로 제한한다. 누적 경로 길이로 진행 위치를 구한다. 지구 전체를 위한 정밀 측지 엔진이 아니다.
4. 근접 거리 → 진행 위치 → 고정 문자열 ID 순으로 기본 순위를 정한다. 이미 고른 소재와 다른 소재를 우선하되 적격 후보 범위 안에서만 선택한다. 같은 장소·같은 ID·80m 안의 같은 `storyKey` 중복은 제거한다.
5. 최대 3개 선택 후 진행 위치 → ID 순으로 정렬하고 표시 순서를 1부터 부여한다. 경로를 여러 번 지나면 가장 이른 최근접 위치를 쓴다. 빈/퇴화/잘못된 경로는 0개다.
6. 날짜는 `YYYY-MM-DD`로 주입한다. 앱은 서울 기준 날짜를 전달한다. 행사 유형을 추가하면 시작 30일 전부터 종료일까지 양끝 포함해 표시한다. 잘못된 날짜나 역전된 기간은 제외하며 저장된 `days_until_start`를 읽지 않는다. 현재 행사 콘텐츠는 채택하지 않았지만 조건은 합성 테스트로 검증한다.
7. 산책을 시작할 때 재선별하지 않는다. 시작 전 확정한 연결 스냅샷을 세션 종료까지 유지한다. 기록/게시글로 스팟 방문 상태를 저장하지 않는다.


브라우저에서는 **http://localhost:3000**을 사용한다. README의 카카오 허용 도메인은 localhost:3000이다. 지도 키는 기존 `NEXT_PUBLIC_KAKAO_MAP_KEY` 설정/목업 기본값을 사용하며 새 인증 정보를 추가하지 않았다. 기존 서버가 있으면 해당 프로젝트인지 확인 후 활용한다.

- `/`: 실제 생성·선택 흐름. 경로에 따라 0~3개를 선택한다. 위치를 바꾸지 않고 생성하면 스팟이 없을 수 있다.
- `/?preview=course`, `/?preview=walk`: 기존 고정 코스/산책 미리보기. 현재 세 적격 장소와는 반경이 맞지 않아 **0개 상태**가 재현된다.
- `/?preview=spots`: **development에서만** 3개의 실제 장소를 주변에 둔 가상 경로를 선택한다. 실제 보행 가능한 경로로 검증하지 않았다는 안내가 있고, 산책 중에도 안내를 유지한다. 앱의 일반 코스 생성에는 쓰이지 않는다.
- `/dev/spots`: **development에서만** 정제된 5개 이야기를 검토한다. 미검증 두 장소는 ‘위치 미검증’으로 표시하고 지도는 렌더링하지 않는다. 위치가 확인된 3곳도 여기에서는 ‘코스 연결 없음’으로 표시한다.
- production에서는 `/dev/spots`가 404이고 `?preview=spots`를 무시한다. 기존 `course`/`walk` 미리보기 동작은 유지한다.

브라우저 회귀 검증은 Chrome과 Playwright가 설치된 환경에서 개발 서버를 켜고 실행한다. 이미 설치된 Playwright 경로를 지정할 수 있어 앱 의존성을 바꾸지 않는다.

```bash
PLAYWRIGHT_MODULE_PATH=/absolute/path/to/node_modules/playwright node scripts/verify-spots.cjs
# 프로젝트에 playwright가 설치돼 있다면: node scripts/verify-spots.cjs
```

검증은 별도 Chrome 컨텍스트의 저장소·GPS 모의 입력을 사용한다. 기존 사용자의 기록이나 브라우저 탭을 수정하지 않는다. 캡처와 결과는 `output/spot/`에 생성된다.

## 후속 과제

- 신수동 공원 구간 geometry와 광흥창 터 범위를 공식 자료/현장 대조로 확보한다.
- 세 점형 후보의 출입구·보행 접근성·위치 오차를 현장 검증한다. 대표 좌표에 가까운 것과 실제 접근 가능한 것은 별개다.
- 자료/지도 제공자의 운영 재사용 조건, 원자료 갱신 방법, 최근 운영 상태를 확인한 뒤 운영 데이터 승격을 검토한다.
- 실제 도보 경로 엔진 도입 시 거리 계산의 투영·범위와 100m 가정을 재검토한다. 현재 선별 결과는 수학적으로 생성한 목업 경로 주변 결과다.
- 행사 최신성·취소·예매 상태와 상권 경계의 공간 기준을 해결하기 전에는 그 유형으로 화면 개수를 채우지 않는다.
